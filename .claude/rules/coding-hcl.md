# OpenTofu roots

Checked by: `tofu fmt -check -recursive`, `tofu validate` and the plan of every root a PR touches (`pull-request-plan.yml`), with the rego rules `naming`, `tags`, `regions`, `catalog` and `trusted-code` run on each plan (`policy.md`). Names are in AGENTS.md "Names" (spec 03).

## What is written by hand

- **`stamps/<lz>/<folder>/`** holds `stamp.yaml` only. Its `main.tf` and `.terraform.lock.hcl` are generated by `tl-platform/stamps/<template>/generate.ps1` at the template's pinned tag, and never edited (AGENTS.md "Rules"); the `stamp-create` skill runs it.
- **`landing-zones/<lz>.yaml`** is data; `landing-zones/_root/` turns each file into one call of the `landing-zone` module. Change the module in `tl-platform`, never a copy here.
- **`platform/azure/<root>/`** and **`global/<root>/`** are hand-written roots: `backend.tf`, `providers.tf`, `variables.tf`, then one file per concern (`groups.tf`, `policy.tf`, `hub-<code>.tf`).

## Rules

- **Data drives resources.** A root reads `catalog/*.yaml` with `yamldecode(file(...))` in `locals` and creates resources with `for_each` keyed by a stable id (a slug, a code), never by a list position. Adding a tenant or a product is a catalog change, not a `.tf` change.
- **Layers point one way:** platform → landingzones → stamps; global reads the catalog and the stamps' outputs. A root never reads the state of a later layer.
- **Every resource that takes tags carries the four tags** (`Product`, `Customer`, `EnvironmentType`, `EnvironmentName`); `tags.rego` fails the plan otherwise.
- **Modules are pinned by tag:** `source = "git::https://github.com/TrislabCompany/tl-platform.git//<path>?ref=<module>/vX.Y.Z"`. A bump is its own PR (`rollout-module` skill), ring by ring.
- **Providers are pinned** in `providers.tf` with `~>`, and the lock file is committed.
- **Nothing is applied by hand** (AGENTS.md): no `tofu apply`, no portal change. A drifted resource is fixed by a PR, or imported with an `import` block.
- **Moving a resource** within a root uses a `moved` block, so the plan shows no destroy; removing a root is planned with `-destroy` (AGENTS.md).
- Every root and every non-obvious resource has a comment saying why, with the spec section or ADR it follows.
- No secrets, subscription ids of clients or personal data in code: ids come from `data` sources or the Environment's variables.
